## 2. ⚠️ 待修 A：末段仍宽一条缝（均分只做了一半）

现状：N 个周期平铺 `P = 跨度/N`，只掐掉最后一条缝 → 末段 = `P`，其余 = `P − gap`。

解析实测（遮罩直接采样，不经像素）：

| 参数 | 普通段 | 末段 | 偏差 |
|---|---|---|---|
| 300° / 70 段 / 缝 1° | 3.286° | 4.284° | +30.4% |
| 270° / 90 段 / 缝 1° | 2.000° | 3.000° | **+50.0%** |
| 300° / 70 段 / 缝 3° | 1.286° | 4.284° | +233% |
| 300° / 70 段 / 缝 10% | 3.857° | 4.284° | +11.1% |

真均分应当是「N 段 + N−1 条缝平铺」：

```
实际节距 Q = (跨度 + gap) / N          ← 比 跨度/N 多摊一条缝
段宽     B = Q − gap = (跨度 − (N−1)·gap) / N   ← 所有段真正等宽
最后一条缝 = [跨度, 跨度+gap)          ← 落在弧外, 自然不画
```

### 改法（最小）

`ringrender.js` `ringSegGeom()`（168–197）：

```js
const nominalP = (full ? 360 : span) / N     // 名义节距: 夹取/显示/导出仍用它
// ... segGapDeg / segGapPct 求出 gap（上限仍 nominalP*0.9）...
const P = full ? nominalP : (span + gap) / N // 开口弧: 实际节距多摊一条缝
return { N, P, nominalP, gap, ... }          // P 继续喂掩码, 语义自洽
```

掩码本身**不用改**：`ringSegMaskDeg(rel, pitch=P, gap)` 里 `bar = P − gap` 自动就是 B。
（也可以额外导出 `nominalP` 给"节距"显示，UI 从 `跨度/N` 改成 Q 更贴实际。）

### 同时必须删掉 `endDeg` 早返回

`ringSegmentMaskDeg` 205–218 的 `if (endDeg != null && rel >= endDeg - gap) return 1` 与调用点
（`1424`、`1560` 的 `endDeg: segG.open ? segG.span : null`）要一起删。原因：换成 Q 之后
`[跨度−gap, 跨度)` 已经落到最后一条缝里，当 `gap > B`（gap 上限 0.9·名义节距时必然发生，N≥2）
这段强制点亮会把最后一条缝重新点亮，等于没修。

### 自检兼容性

`check-ringseg.mjs` 295–325 的两条断言在 Q 口径下**依然成立**：
亮段数 = N ✓、`暗区总宽 ≈ (N−1)×gap` ✓（只是末段变窄、缝位置平移）。
建议补一条断言把均分钉住：`max(段宽) − min(段宽) < 0.01°`。

## 3. ⚠️ 待修 B：镜像对分割弧错位（本次改动的回归）

| 场景（`startDeg=-90`） | 与"真·水平镜像"不等的像素 |
|---|---|
| `segOn` 关（任意跨度 / 相位） | **0.000%** ← 基线正常 |
| `segOn` 开，300° 弧，相位 0° | **9.993%**（5756 px） |
| `segOn` 开，300° 弧，相位 2.5° | 9.899% |
| `segOn` 开，整圈，相位 2.5° | 2.441%（旧问题，同样由本次暴露） |

根因：`mirrorRingX()`（`ringrender.js` 147–152）仍是旧口径

```js
const P = 360 / N
out.segPhaseDeg = -((phase) + (span % P))
```

镜像**同时翻了起始角和弧向**，而相位是"相对弧起点"的定义 → 相位本身不变。
实测把相位原样保留，四种组合全部 **0.000%**。

### 改法

删除 147–152 整块（相位不动；`out.segPhaseDeg` 保持原值即可）。
若担心"点两次回原样"：相位不变 → 二次镜像天然还原 ✓。

### 连带要改的断言

`scripts/check-ringrange.mjs:144` 目前钉的是旧行为：

```
'span=270°, N=90 → 周期 4°, phase -2°'  near(x.segPhaseDeg, -2)
```

要改成"相位不变"，并建议加一条像素级对拍防回归（放在 `check-ringseg.mjs`）：

```js
// render(ring) 与 render(mirrorRingX(ring)) 的水平翻，逐像素 alpha 差 > 8 的个数应为 0
// 画布 240, 圆心 x = 119 → 翻折轴 x' = 238 - x；segOn 关/开、跨度 300/360、相位 0/2.5 各测一遍
```

（复核用的临时脚本已按此写好口径，可直接复刻；`segOn` 关时必须恒为 0 才能证明问题只出在分割。）

## 6. 2026-10-22 角向 AA（分割缝边）修正

- **遮罩改成带符号距离**：段内 `+d`、缝内 `−d`，过渡带跨边界对称展开
  `缝内 −AA/2 → 0 · 边界 0.5 · 段内 +AA/2 → 1`。旧写法只在段内做斜坡
  （边界 0.5 → 缝里立刻 0），加大 AA 也只会软段内一侧，缝的另一侧始终是硬边，
  这就是“分割线不直”的主因。
- **AA 参数语义统一为“总过渡宽度”**（px），与固件 `ring_seg_aa_color()` 同式：
  `t = 0.5 + sBody/AA`。默认 2.0px（旧默认 0.8），圆环弹窗「分割 → AA」改成
  0..4px 滑杆 + 0 / 1.5 / 2.0 快捷键，0 = 硬边。
- **导出 / 运行期**：导出仍是 `RING_SEG_AA_X10`（0.1px）；固件新增
  `Ring_SetSegAA(x10)` / `Ring_GetSegAA()`，改完立即整弧重画，便于板上现场 A/B。
- **对照图**：`ring-seg-preview/aa-sweep.png`（上排固件 host、下排网页）。
  40% 缝宽（≈3.1px）下，1.5px 保留分段感，2px 以上槽心开始溶解。
- **自检**：`scripts/check-ringseg.mjs` 增加对称性、宽度单调性、`0 = 硬边` 断言；
  结构断言改用 0.2px 窄 AA，避免 1° 缝在 240px 上被 2px AA 抹平导致的采样抖动。

## 8. 2026-10-22 沟槽 AA / 端点 AA + 基本页布局

- **AA 分两类，不是左右两端**：
  - **沟槽 AA**（`segAA`）＝ 段与段之间缝隙的过渡宽度，0..4px；
  - **端点 AA**（`aaEdge`）＝ **起始角 / 结束角**两条静态端面的过渡宽度，0..6px，
    一个值同时管两端，只在圆端帽关掉时生效。
- 端点 AA **单边向外**：端面内保持满覆盖，只在端面外侧铺 AA，所以高亮区不被侵蚀，
  50% 线落在端面外 AA/2 处，圆弧视觉上向外延伸。
- 端面外延的颜色不是一条纯 fill 亮条，而是**该端自己那一段的沟槽色**
  （起点用第 0 段、结束角用最后一段）：先把沟槽格延续到端面外，再用 alpha/底色淡出。
  这样起点/结束角不会出现"实心亮块"或跨到上一周期的错色。
- 端点 AA **不碰进度前沿**：未满档（10/35）时填充末端是硬边；只有满档时填充末端
  才与结束角重合，由结束角过渡负责。
- `ringArcEndAA()` 的 `aa` 可以是数字（两端同宽）；内部仍兼容 `{start,end}` 形式。
- **导出**：`RING_SEG_AA_X10`（沟槽）+ `RING_AA_EDGE_X10`（端点）；
  固件 `Ring_SetSegAA(x10)` / `Ring_SetEdgeAA(edgeX10)` 各自运行期可调。
- **布局**：删除「快速范围」卡片；「分割」整张卡片挪到「基本」页、几何下方
  （紧跟在厚度/留边/边缘 AA 之后），效果页只剩效果/白斑。
- **自检**：`check-ringseg` 验证"端点 AA 一个值同时作用 2°/178°"且
  "沟槽 AA 不影响端点"；`check-ui-render` 钉住分割卡片在 basic/几何之后、
  快速范围已删、沟槽 AA / 端点 AA 两个控件存在。

## 9. 2026-10-23 档位分割点同源 (RING_SEG_SPLIT_X10)

- 新增 `segSplit`（0..10，默认 5）：档位分割线在槽里的位置。
  - 0 = 段体末尾（旧行为），5 = 槽中点（当前 MCU），10 = 下一段开头。
- 网页预览不再用 `value/steps × 跨度` 线性等分，改用与固件同一条整数链：
  ```
  lit    = round(value × N / steps)
  fillEnd = lit×P − gap×(10−split)/10        (整数 Q8, C 的 /10 向下取整)
  units   = ceil(fillEndQ8 / 128)            (0.5° 向上取整, 同 Ring_SegSweep)
  ```
  低档不再切进下一段 body；网页/板子的末端在 0.5° 网格上一致。
- 导出 `RING_SEG_SPLIT_X10`；固件 `Ring_SegSweep()` / `ring_fill_end_set()` 读同一个宏。
- 端点 AA 同步到 MCU 这一版：
  - 静态端点颜色 = 该段 **body/groove 各半**（不是纯槽色，也不是纯 fill）；
  - 未满档的**进度前沿**也做一段向外 AA，颜色取前沿处段/槽色；
  - 仍全部只向外淡出，不侵蚀高亮区。
- 自检：`check-ringseg` 增加 split 0/5/10 的填充末端扫描（≈7.0/8.0/8.5°）和
  进度前沿 AA 的渲染断言。
